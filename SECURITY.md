# Security and privacy

- This public repository is a companion reference, not a learner template. Mona lives only in the participant's existing private Lab 1 copy. Do not post completion commands, learner screenshots or account details here.
- Each participant continues with one private repository and one private Project. No bootstrap, extra repository, additional token, application key or instructor provisioning is required by this companion.
- The only workflow performs offline content checks with Node built-ins. It requests contents read only, persists no checkout credentials, installs no dependencies and uses no secrets or Projects API. It does not create issues, Projects or learner resources.
- Official Actions are pinned to full commit SHAs. Pull request content is checked without a privileged trigger or write permissions; do not add credential-bearing automation to this guide.
- Keep normal Git authentication in your credential manager/browser. Never paste secrets into a command comment, a repository file or a public report. Repository-local Git author metadata is not authentication.
- Use synthetic training data only, not real BSP data or original proposal documents. Downloaded TSV exports and account screenshots stay local; do not publish them with the guide.
- Every Lab 3 activity is self-confirmed, not API-verified or AI-graded. A missing feature, local content-check success or a posted command does not prove a native Project activity occurred. Neither companion checks nor Mona completion establish independent review, approval or compliance.
- Respect account entitlements, organization protections and inherited access. Do not weaken them to complete a workshop activity.

Report a vulnerability privately through the repository owner's contact on the [organization profile](https://github.com/alvine-aurelio-org). Do not include an actual credential in a public issue. If a credential was exposed, revoke it through its issuer's supported process.
